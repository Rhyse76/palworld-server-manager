# RuneScape: Dragonwilds — dedicated server reference

**Verified against a real install and a live server run (2026-10-04).** The test server was started directly (not yet through the app) and created a joinable session.
[dedicated servers how-to](https://dragonwilds.runescape.com/news/how-to-dedicated-servers),
the [official wiki](https://dragonwilds.runescape.wiki/w/Dedicated_Servers), and hosting-
provider guides for the literal ini text.

## Config: one small ini

A fresh install ships **no** ini and no `RSDragonwilds/Saved` folder. This is the file after
a real first start (the app wrote the five documented keys; the server added the rest):

```ini
;METADATA=(Diff=true, UseCommands=true)
[SectionsToSave]
bCanSaveAllSections=true

[/Script/Dominion.DedicatedServerSettings]
ServerGuid=<generated by the server>
OwnerId=<32 hex characters, no dashes>
ServerName=My Community
DefaultWorldName=Rune Valley
WorldPassword=
PlatformPolicy=Crossplay
bAllowSendingCrashDumps=True
```

Confirmed live behavior the adapter handles:

- **The server rewrites the file at startup** and **removes the `AdminPassword` line** after
  reading it (a second start without the line works, so it is stored elsewhere). The Config
  page therefore always shows Admin password blank; a blank value for a key not in the file
  is never written, and typing a new value sets it again.
- **`OwnerId` must have no dashes.** The dashed GUID form logs `Session setting [OwnerId] is
  too long` then `CREATE SESSION - Failure`; the server keeps running but nobody can join.
  `config::write` strips dashes.
- `ServerGuid` is the server's own identity and is hidden from the Config page.
- `PlatformPolicy` defaults to `Crossplay`; other allowed values are unknown, so it stays a
  free-text field.
- Jagex: changes made while the server is running are lost — the Config page's
  stop-the-server-first guard is enabled for this game.

## Launch

The stock `start.bat` people use is just `RSDragonwildsServer.exe -log -NewConsole` followed by
`pause` — nothing the app needs to recreate. The adapter passes `-log` only; with the app's own
console that was enough for a stable run with visible log output.

The game port is the `-port=<n>` launch argument, not an ini key. The adapter passes none
(default 7777); a second server on the same PC needs `-port=7778` in the profile's "Extra
launch arguments".

## Stopping

The server shuts itself down on a console **Ctrl+Break**: it logs `Engine exit requested
(reason: ConsoleCtrl RequestExit)` and is gone about 2 seconds later. `GameSpec.
exits_on_console_break` is set for this game, so `server::stop_for` (manual stop, scheduled
restart, auto-update, crash-watchdog paths all go through it) sends that first and force-kills
only as a fallback. Verified live through `start_for`/`stop_for`, with both a visible and a
hidden console.

- Plain Ctrl+C is ignored by the server; a window close also triggers the exit request but
  only works with a visible console.
- **No save on exit was observed.** The log ends at the exit-request line and the `.sav`
  timestamp did not change, on an empty world with no players. So this is the engine exiting
  on its own terms rather than being cut off mid-write — not a guaranteed final save.
- A plain force kill also left the (empty) test world loadable.
